# Endpoints that declare no authorization on the route itself.
#
# BSEC-003's second verification criterion, recorded 10 November 2026 with 478 entries out of 1,100
# composed endpoints.
#
# These are not unprotected. The platform enforces a request in one of two places -- on the route
# with RequireAuthorization, or on the request type with [Authorize], which AuthorizationBehavior
# applies in the CQRS pipeline -- and every one of these takes the second. Financial's 112
# endpoints and Community's 100 are the bulk of it. Since BSEC-003, a request type that declares
# NEITHER [Authorize] nor [AllowAnonymous] is refused by that behaviour and rejected by
# RequestAuthorizationArchitectureTests, so the second place is now as enforced as the first.
#
# What this file buys is the naming property the audit asked for and the old rule could not give:
# "removing .RequireAuthorization from any one endpoint makes it fail, naming that endpoint". The
# rule that reads this holds the set exactly, so an endpoint that loses its route declaration joins
# it and is named. The previous rule counted endpoints with authorization and asserted the count
# was over a hundred, which said nothing about any particular one.
#
# The list only shrinks. Moving a module to route-level declaration deletes its lines; nothing is
# ever added, because an addition is an endpoint that just lost a declaration it had.
#
# Two entries are neither CQRS nor authorized and are the deliberate exceptions: the liveness and
# readiness probes, which an orchestrator calls with no credential and which BSEC-002 also exempted
# from the transport rate limiter.
#
# Format: <METHOD[,METHOD]> <route pattern>
